# ChatGPT bridge: instructions for AI agents

You can generate images through the user's ChatGPT tab. Follow this exactly.

## Setup check (do this first)

1. Run `node --version`. It must be 18 or newer. No `npm install` is needed: there are no dependencies.
2. Run `node bridge/tabs.mjs`. It lists the ChatGPT tabs the extension sees.
   - **Empty list**: the user must do the install from README.md (load `extension/` in `chrome://extensions`, open chatgpt.com logged in). Ask them, then check again.
   - **No `★`** (no working tab chosen): ask the user which tab to use, then run `node bridge/tabs.mjs use <id>`. Never pick one of their other conversations on your own.
3. You never start the browser or open tabs yourself. The user's own browser does the work.

## Make an image

1. Write a job folder:
   ```
   job/
     prompt.txt      the full prompt (plain text)
     refs/           optional references, attached in name order: 1-….png, 2-….png
   ```
2. Run:
   ```bash
   node bridge/submit.mjs job out.png --topic <style>
   ```
   - Use **one topic per style** (e.g. `ui`, `characters`, `symbols`): the same topic reuses the same ChatGPT conversation, so the style stays consistent.
   - It prints the steps (`upload`, `generating`, `download`) and exits 0 with the image saved, or 1 with `ERREUR: …`.
   - It can take 1 to 3 minutes. Run it in the background and wait; do not poll the tab.
3. Several images: run the jobs **one after the other**. A loop in a shell script is fine. Never in parallel.
4. To fetch an image already in a conversation without generating: `node bridge/submit.mjs any-folder out.png --chat <url> --grab [--back N]`.

## Ask for a review (text answer)
ChatGPT is also a good image critic. Before showing a picture to the user, ask it:
```bash
node bridge/submit.mjs job answer.txt --ask --topic <style>-review
```
Same job folder (`prompt.txt` = the question, `refs/` = the images to judge). The written answer is saved in
`answer.txt`. A thinking model can reason for several minutes before writing: the job waits up to 25 min and the tab reports a
heartbeat every 20 s (`answer N chars via role|page · elapsed · url · hidden · user/assistant counts · « first words »`).
Use a separate review topic so the critique does not pollute the generation conversation. Ask precise
questions (what is wrong, where, how bad) and act on the answer before the user sees anything.

Review lessons (grumpy-mole, 2026-11-12):
- Keep the "high" thinking effort for reviews even when a question takes 5-10 min (owner: quality before time). A
  watchdog may kill a question only when nothing happens (extension unseen for 1 min, or 15 min in total), never while
  ChatGPT is still thinking.
- Put a unique request id at the end of every question and keep only the text after it: the bridge can otherwise read
  the previous answer of a shared conversation. One fresh topic per question.
- Give ChatGPT its role for the subject (for a rig: "senior Spine 2D animation and rig expert"): its remarks then
  name the real fix (draw order, overlap, mesh) instead of illustration advice.
- ChatGPT's usage limit is shared by the whole account: images generated by the user in another window block the
  bridge's uploads ("patientez N minutes avant d'importer"; every file input of the composer is disabled).

## Prompt tips that work
- Ask for a **plain flat light grey `#c8c8c8` background** when you need to cut the image out. Never ask for "transparent": you get a fake checkerboard.
- Give the exact format (e.g. "square 1:1", "portrait 2:3") and say what must not appear (text, watermark…).
- Refer to references by number ("reference 1"), in the order of the `refs/` files.
- **Silent refusals:** an answer with no image and no text (`ChatGPT answered without an image:` with nothing after it,
  about 90 s each time) usually means the image was blocked. Do not retry the same prompt more than twice: change the
  wording. Weapon / explosive vocabulary triggers it even for harmless cartoon props ("TNT", "dynamite",
  "detonator", "bomb", "explosive", "skull-and-crossbones"): describe the object itself instead ("an old wooden
  plunger box with a T handle and two red wires", "a red paper stick with a short cord"), and keep the theme in the
  references rather than in the words.

## Safety rules built in (do not work around them)
- **One message = one image, at most one automatic retry.** The tab re-sends only when ChatGPT clearly made no image
  (it asks for the references, or shows a failure with a retry button). A question or any other text fails the job:
  read it, fix the prompt, then submit again yourself.
- **Stopping `submit.mjs` cancels the job** (Ctrl-C, kill, timeout): the tab clicks ChatGPT's stop button and sends
  nothing more. Never leave a job running in the background without its `submit.mjs`.
- **Same request twice = one job**: a second identical `submit.mjs` waits for the first one instead of generating again.
- **References are checked after sending**: if our message shows fewer images than `refs/`, ChatGPT is stopped and the
  job fails (`message sent with n/m references`).
- **Pause**: when ChatGPT is logged out or says the quota is reached, the bridge pauses and refuses every job
  (`submit.mjs` exits 4 with `pont en pause`). Tell the user; only they resume it (popup button « Reprendre », or
  `curl -X POST http://127.0.0.1:3777/resume`). Never resume on your own.
- An image that arrives after its job was cancelled is still saved in `~/.aki-chatgpt/images/<id>-late.png` (it was
  paid with quota). The popup history shows `⚠ n envois` when a job sent more than one message.
- Chrome is never brought to the front: the working tab is woken by a message. Put the ChatGPT tab in its own Chrome
  window, not minimised, so the browser does not slow it down.

## When it fails
| Error | What to do |
|---|---|
| `no ChatGPT tab` / `Aucun onglet de travail choisi` | Ask the user to open chatgpt.com and choose the tab (extension icon, or `bridge/tabs.mjs use <id>`). |
| `ChatGPT answered without an image: …` | Read the quoted answer and fix the prompt (content refused, too vague). |
| `pont en pause (quota)` / `(logged out)` | Stop. Tell the user. Do not retry until they resume the bridge. |
| `message sent with n/m references` | Check the `refs/` files (format, size), then submit again once. |
| `le pont ne répond plus` / `ne connaît plus ce job` | The bridge restarted. Fetch the image with `--grab` before submitting again. |
| `timeout: file input` (files=N, all disabled) | ChatGPT's import limit. Wait (the user can see "patientez N minutes" on the attach button), then retry. |
| an answer shows in the tab but the popup stays on « ChatGPT réfléchit » with 0 characters | The answer reader missed it (0.6.5 fixed the folded-prompt case: it now reads after the last « ChatGPT a dit : »). Tell the user, look at `content.js` `answer()`. |
| `timeout: composer`, `timeout: …` | ChatGPT's interface changed. Tell the user the selectors in `extension/content.js` (`SEL`) need updating. |

Keep the volume low: this is the user's personal ChatGPT account.
